Sidetrack 0.4.1 is the tester round on top of 0.4.0-rc1: the two new services
(Navidrome, Jellyfin) keep their shape, and this round is about the library, search and the
keypad. Nothing needs reinstalling — same package, same certificate, so it updates in place.

## Library

- **Compact rows.** Appearance gains an optional layout that fits a fifth media row on screen:
  82 dp rows, 64 dp artwork, a tighter text block. It applies to every track, album, playlist and
  show row, and the gutters, swipe reveal and queue reorder stay in step with the row pitch.
- **Row gutters.** Artist rows offer Follow and Artist radio, album rows Save and Add to queue,
  playlist and show rows their own actions, and search gives its non-track results the same
  gutter the library has. Destructive actions stay out of the gutters.
- **Each category keeps its place.** Albums, artists, playlists and shows now cache their own page
  set, so walking the category row no longer refetches page 0 and no longer throws away pages
  loaded past the first. A stale category revalidates behind its list: no spinner, no cleared
  rows, and an error with content already on screen stays a notice.
- **Held arrows switch category.** Holding Left or Right on the category row steps to the
  neighbouring category; the row the user last settled on is restored with its scroll position.
  A switch started from the row keeps the cursor on the row instead of handing it to the list.
- **Playlist editing is reachable.** Create a playlist, add tracks to it, remove them again. Edit
  permissions are modelled per playlist, so an entry only appears where the provider allows the
  write, and cached track counts follow an edit instead of drifting.

## Search

- **Results page per query and category.** Search is the one screen that pages five lists at once;
  it used to hold a single flattened result set, so toggling a scope replaced all five lists from
  the top. Pages now fold into a per-query, per-category cache that is cleared only when the query
  changes.
- **Holding Left or Right switches scope**, skipping scopes that are switched off or that the
  service cannot answer, and returning into a scope restores the row and scroll it was left at.
- Up from the first result returns to the category row, a selected category keeps the cursor on
  the row, and a scope that disappears from the queried set moves the selection and the cursor
  together instead of leaving the cursor behind.

## Keypad

- **Welcome reads the keypad that is attached.** Sidekit 1.9.3 detects the module from the input
  device that names it, so the page teaches the module the hardware names instead of the one that
  was remembered — the D-pad of a game controller identifies the controller, which reading the keys
  alone cannot do. T9 is recognised again: on this firmware its slides report as the phone's own key
  device, where its digits identify them because no other module types one. A
  key press gets an answer: the row it demonstrates lights up in the case accent, and the Options
  row lights while the Options bar is open. "Select keyboard" opens the page and steps to the next
  module on tap, with or without a Sidekit host, so a keypad the app guessed wrong can be corrected
  on the page that teaches it. The cheat sheet's keys now share one column, so every sentence
  beside them starts on the same line, and the page's sections are separated instead of running
  together.
- **The Sundial plays.** Centre is play/pause, and the Previous/Next edges are media keys; the
  headset hook works too. The keys bypass Android's input pipeline (Sidekit re-sends a synthetic
  press after watching for a hold), so the activity translates them itself — one command per
  press, a held key repeats, and a key with no player is left to the platform. This needs Sidekit
  1.9.3, which keeps the Sundial's edges as media keys.

## Menus

- Every Options bar and every row action menu is built from one factory now. Eleven screens used
  to assemble theirs by hand, so the same entry wore a different label, glyph, shape or colour
  depending on where it appeared.
- Colour follows what an entry does: accent for a live option or action, green for an on-state,
  red for destroy, grey only for Close, notices, undo and Cancel. Destructive entries sort last.
- Two visible moves: the queue's **Clear upcoming** now lives in Options (the only list-wide
  destructive action now sits with the list-wide destinations) and gives its place to the Shuffle
  toggle; the queue row action renamed from **Delete** to **Remove**.

## Playback and Home

- **The sleep timer can end with the track**, and both timer modes report what they did: Home and
  Now Playing show a paused-by-timer state instead of a player that mysteriously stopped. The
  countdown measures listening time, so pausing holds it and starting again continues it.
- **Recently played lists what you moved on from.** The outgoing track enters the history only
  when the queue actually switches, and the track playing now is not echoed in that list — it
  belongs to Now Playing.
- **Artwork no longer dies on a JSON null cover**, and history records a track only after the
  switch instead of on every start.

## Providers

- **Jellyfin is on the official 12.x SDK** instead of a hand-written HTTP client, with explicit
  timeouts (30 s request and socket, 6 s connect) and the same paging and field selection the
  screens expect. Creating a playlist now works: Jellyfin answers `POST /Playlists` with a bare
  32-character GUID while every other id carries the dashed form, and the created id used to be
  read as garbage — the form stayed open with "This track isn't available" and invited retries
  that left five playlists behind.
- **Navidrome** splits its transport from its JSON mapping, and **Spotify** splits stall recovery,
  the transport commands the notification can issue, the cache accounting and the AudioTrack
  builder out of its session. Behaviour is unchanged in both; the files are just no longer
  600 lines each.

## Upgrading

- **In place, no uninstall.** Package, signature and version-code chain are unchanged, so an
  existing installation is updated and its data directory is kept. History, queue, resume point
  and settings keep their file names.
- **Built against Sidekit 1.9.3**, taken from the published release rather than a local staging
  build, exactly as the version catalog pins it. The keypad detection the welcome page relies on
  lives there, so the SDK version is not optional.

## Suite status for this tag

- **746 unit and Robolectric tests, green**, product coverage **73.46% line / 48.56% branch**
  against floors of 71% / 45% with the full suite and 58% / 39% for the fast default gate.
- `spotlessCheck`, `lintDebug` and the debug/profile/demo builds are green, and the instrumented
  playback suite runs in CI on API 31 and API 36 as before.
- **The screenshot gate is green again.** The Roborazzi baselines were last recorded at 0.3.6, so
  every screen this round touched failed the verify pass; each diff was checked against the commit
  that produced it and the baselines were re-recorded. The store-catalogue shots render on demand
  (`-PsidetrackScreenshotsRecord`) and no longer count as a gate, which is what they were always
  meant to be.
- **The Spotify module's suite runs again.** Three sleep-timer cases still expected the timer to
  fall back to Off and to tick while idle, both of which changed before this branch; that failure
  blocked the module's coverage gate, so CI on this branch was red. The cases now assert the
  contract `core` already pins.

## Known

- **Jellyfin 10.9 is refused, not supported.** It signs in and then fails every read inside the
  12.x SDK, so the floor is enforced at sign-in.
- **No deletes and no bulk writes on either provider.** Neither implements a delete endpoint, and
  no write takes a collection.
- Spotify library and search need the native bridge (`-PsidetrackNative=true` at build time, which
  both assets below are); without it Spotify falls back to the public Web API, which rate-limits
  the desktop client ID.
